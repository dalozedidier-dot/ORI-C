# Révision proposée du Codebook ORI-C fondée sur les résultats

## 1. Conserver le noyau canonique

Conserver ORI-C comme **Organisation, Résilience, Intégration, Cohérence**. Ne pas remplacer ces termes par de nouveaux acronymes. Ajouter une couche de mesure distincte afin qu’un concept ne soit jamais confondu avec son estimateur.

## 2. Rétrograder définitivement la chaîne centrale

`Histoire → Architecture → Contraintes → Réponse → Inscription → Possibilités` reste un **gabarit causal à instancier**. Une branche doit publier pour chaque maillon une variable, une unité, une incertitude, une intervention et un témoin. Une chaîne partielle ne peut pas être citée comme validation globale.

## 3. Suspendre les six dimensions comme variables validées

`n, G, I, E, Π, H` restent des rubriques descriptives jusqu’à ce que :

- des codeurs aveugles les reproduisent ;
- elles distinguent des transitions d’un même régime ;
- leur information conditionnelle sur le régime soit positive ;
- au moins une améliore une prédiction hors échantillon.

## 4. Remplacer les étiquettes uniques par un profil de mesures

- **Organisation** : topologie, modularité, variables collectives, information causale du niveau.
- **Résilience** : temps de retour, coût de restauration, taille du bassin, probabilité de récupération.
- **Intégration** : synergie PID/ΦID, dépendances fonctionnelles nécessaires, perte de performance après ablation.
- **Cohérence** : compatibilité dynamique entre contraintes, calibration et stabilité inter-environnements.

## 5. Taxonomie obligatoire de la mémoire

Une publication doit classer le signal observé :

1. autocorrélation ou inertie ;
2. retard de relaxation ;
3. hystérésis ;
4. mémoire spécifique rappelable ;
5. modification architecturale ;
6. apprentissage/adaptation.

Le mot « mémoire » sans cette classification devient irrecevable.

## 6. Rendre Pacc calculable

Définir `Pacc(T,C,ε)` par une procédure de reachability ou un échantillonnage probabiliste publié. Déclarer l’horizon, les contraintes, les ressources, le modèle de bruit et ε. Mesurer la même grandeur dans deux branches avant toute revendication transversale.

## 7. Remplacer la carte statique par deux objets

- une chronologie descriptive ;
- un réseau temporel causal avec dates, durées, interventions, conditions nécessaires et incertitudes.

Le gain du réseau doit être mesuré contre la chronologie seule.

## 8. Critère minimal d’apport propre d’ORI-C

Un résultat positif exige simultanément :

- hypothèse et seuil gelés ;
- jeu test séparé ;
- témoin de complexité égale ;
- ablation du mécanisme ;
- identifiabilité suffisante ;
- avantage stable entre fenêtres/environnements ;
- réplication indépendante.

## 9. Séparer trois niveaux de preuve

1. fait disciplinaire sous-jacent ;
2. validation dans un modèle réduit ;
3. valeur ajoutée spécifique d’ORI-C.

Aucun niveau ne se transmet automatiquement au suivant ni entre branches.

## 10. Supprimer ou fusionner les concepts sans rendement

Après le benchmark MDL, toute notion qui n’ajoute ni mesure, ni prédiction, ni intervention, ni compression doit être fusionnée, rétrogradée au glossaire ou retirée du noyau.
